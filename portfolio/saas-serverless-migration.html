Moving a client communication platform to AWS serverless

A migration to managed AWS services (API Gateway, Step Functions, DynamoDB) that kept every business flow working.

Context

A SaaS platform that connects clients and their families with admin teams, automating repetitive updates to save time, effort, and cost.

Challenge

The existing system had to move to a new platform without breaking the communication flows that clients depended on every day.

Approach

  • Defined the architecture for new services on AWS: API Gateway, Step Functions, DynamoDB, RDS, ECS, and S3.
  • Investigated and compared migration approaches.
  • Mapped customer requirements into milestones, releases, and quality targets.
  • Created test viewpoints and a PR review checklist for the team.

Key decision & trade-off

Build the new services on managed AWS services: API Gateway, Step Functions, DynamoDB, and ECS.

Ties the platform to AWS, in exchange for less infrastructure for the team to run.

Result

  • Migration to the new platform with business behavior preserved.
  • Releases planned against agreed milestones and quality targets.
